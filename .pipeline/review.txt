## Section 1: Blocking Issues

### [BLOCK-01] correctness — examples/blog-app/src/App.ts lines 26 & 38-41 — Duplicate ApiGatewayPlugin instantiation causes EADDRINUSE on startup

Severity: Runtime crash — server fails to start on port 3000.

ApiGatewayPlugin is instantiated twice:
- Line 26: manual instantiation (const apiGatewayPlugin = new ApiGatewayPlugin())
- Line 30: also loaded via loader.loadAllFromForgeJson (because forge.json lists it)

Both instances end up in allPlugins (lines 38-41). Both are called with init(ctx) and start() (lines 53-62). The first instance binds port 3000; the second fails with EADDRINUSE.

The deduplication logic at lines 32-36 (filter by loadedNames) only applies to corePlugins, not to allPlugins. The duplicate remains in allPlugins and both start() calls execute.

Fix: Exclude manually created plugins from loadedPlugins before merging into allPlugins.

---

### [BLOCK-02] correctness — packages/forge-cli/src/commands/new-plugin.ts line 29 — Unquoted @ in scaffolded plugin.yaml causes YAML parse failure

Severity: forge check fails for every plugin scaffolded by forge new.

The template generates: name: @forge/${name}

In YAML 1.1 (the default for the yaml npm package), a plain scalar starting with @ is a reserved character and causes YAMLParseError. The test results confirm this.

The existing Phase 2 plugin.yaml files (db-plugin, auth-plugin, events-plugin) all use properly quoted names. Only the template in new-plugin.ts produces invalid YAML for newly scaffolded plugins.

Fix: Quote the name field in the template (line 29): name: "@forge/${name}"

---

### [BLOCK-03] completeness — packages/events-plugin/src/index.ts lines 35-39 — events:adapter-changed event never emitted on Redis fallback

Severity: API contract violation — the event declared in plugin.yaml is never fired.

plugin.yaml declares events: events:adapter-changed. The PluginSpec.events also includes this event. However, when Redis connection fails and the adapter silently switches to memory mode, no event is emitted.

Fix: Emit the event inside the catch block: this.bus.emit("events:adapter-changed", { from: "redis", to: "memory" });

## Section 2: Non-Blocking Issues

### [SEC-01] quality — packages/auth-plugin/src/index.ts line 29 — Hardcoded insecure JWT secret

this.secret = "change-me-in-production" is the default if auth.jwtSecret is not configured. In production, tokens are signed with a predictable secret. The healthCheck() method also reports status: "healthy" even when the insecure default is active. Non-blocking but should be addressed before a production release.

---

### [SEC-02] correctness — packages/db-plugin/src/index.ts lines 35-38 — pg/mysql drivers silently fall back to SQLite

The init() method uses SqliteAdapter for both pg and mysql cases. Configuring db.driver: pg silently uses SQLite with no error. MongoAdapter is correctly instantiated for mongodb, but pg and mysql are stubs.

---

### [QUALITY-01] quality — examples/minimal-app/src/hot-reload.ts lines 84-113 — Hot reload does not actually reload the plugin

reloadPlugin() logs and emits bus events, but never calls plugin.stop(), reimports the module, or reinitializes the plugin. Non-blocking if documented as "rebuilds dist; full restart still required".

---

### [QUALITY-02] type-safety — packages/auth-plugin/src/index.ts lines 77-93 — middleware() defined but never called

auth.middleware() is defined but examples/blog-app/src/handlers/index.ts uses a separate local authMiddleware() wrapper instead. The middleware() method is dead code.

---

### [QUALITY-03] type-safety — packages/forge-core/src/plugin-loader.ts lines 117-127 — provides and events silently discarded

loadManifest() always reads from package.json first. If a plugin has both package.json and plugin.yaml, provides and events from plugin.yaml are silently replaced with empty arrays. Creates a latent bug.

---

### [QUALITY-04] edge-case — packages/events-plugin/src/index.ts line 92 — once() does not invoke local handlers

once() calls this.bus.once() but does not update this.localHandlers. For purely local subscriptions, the once handler may not fire correctly. Not currently exercised because App.ts uses bus.once() directly.
